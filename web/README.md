# HospitalGym web app

Next.js (App Router) + TypeScript + React Three Fiber + Zustand + Tailwind. One 3D hospital scene, drawn entirely from
the layout JSON, reused by four modes: Play, Watch, Compare, Trade-off. Everything is built against `contracts/`
(`api.md`, `snapshot`, `layout`, `rollout`, `metrics`, `actions`, `catalog`).

## Run

```bash
cd web
pnpm install
pnpm dev            # http://localhost:3000
pnpm build          # production build, type-checked
pnpm start          # serve the build on :3000
```

- `NEXT_PUBLIC_API_URL` sets the server (default `http://localhost:8000`). For one browser tab you can also append
  `?api=http://host:port` to the address.
- Deep links: `/?mode=play|watch|compare|tradeoff`, `&rollout=<id>` (Watch), `&a=<id>&b=<id>` (Compare),
  `&gfx=low` (no shadows or antialiasing, for weak GPUs).

## Online and offline

Every call goes through `lib/api.ts`. If the server does not answer, the same call resolves from the files in
`public/fixtures/` and the result is marked `fixture`. The status pill in the top bar shows "Live" or
"Offline · fixture", and its popover lists the simulator, language model, voice and data services from `/api/status`.
Fixture data is labelled wherever it appears (chips on panels, a banner on the trade-off chart).

`public/fixtures/` is generated by `pnpm fixtures` (`scripts/make-fixtures.mjs`) from `contracts/fixtures/`,
`contracts/*.yaml`, `catalog/*.yaml` and `catalog/hospitals/rwjuh_nb.layout.json`:

| File | Stands in for |
|---|---|
| `status.json`, `enums.json`, `metrics.json`, `scenarios.json`, `hospitals.json`, `managers.json` | the endpoints of the same name |
| `catalog.json`, `catalog-refs.json` | `/api/catalog`, `/api/catalog/ref/*` (built from the real `catalog/*.yaml`) |
| `layout.fixture.json`, `rwjuh_nb.layout.json` | `/api/layout/{id}` |
| `rollouts.json`, `rollout.fixture.json`, `rollout.fixture_b.json` | `/api/rollouts`, `/api/rollouts/{id}` |
| `results.json` | `/api/results` |

Two of these are invented for layout work and say so on screen: `rollout.fixture_b.json` is a mechanical edit of the
contract fixture so Compare has a second manager, and the points in `results.json` are typed by hand. Neither is a
simulator or evaluation result.

Offline, Play replays the fixture rollout (knob changes are shown as queued but nothing is simulated), and the human
run is kept in this browser's localStorage instead of being POSTed.

### Trying the live path without the real server

`pnpm mock-server` (`scripts/mock-server.mjs`, port 8010) implements the HTTP and websocket shapes in
`contracts/api.md` with a toy patient flow. It exists to exercise the client; it is not the simulator.
Open `http://localhost:3000/?mode=play&api=http://localhost:8010`.

## What was checked against the real server

With `server/` running on :8000 the screenshot script was run with `--api http://localhost:8000`: status, lists,
layout, catalog refs, the fixture rollout, a live Play run over the websocket (knob queued, stop, final summary, human
run POSTed and shown on the trade-off chart), the validation card, and a live Compare (two sockets, same scenario and
seed, two managers). Server behaviours handled: `hour` acknowledgements with empty metrics are not plotted; `pending`
is read as "not yet applied" and current settings come from `snapshot.kpis.settings`; several `hour` messages may
arrive between snapshots at high speed; `stop` is awaited through `summary.final`; unknown catalog refs (404) show as
"no catalog entry" rather than a fixture; manager and rollout lists are re-read on every mode change.

Compare has two sources: recorded rollouts (one shared replay clock) or "Run live" (two live simulations; each runs
on its own clock, so they can drift a few ticks apart).

## Structure

```
app/                 layout, the single app page, placeholder routes /encounter and /studio
components/
  App.tsx            mode switching, boot
  scene/             the 3D scene (client-only, loaded with ssr: false)
    build.ts         layout JSON -> primitives (floors, walls, beds, scanners, roads, trees)
    Building.tsx     instanced meshes for those primitives, floor labels, context buildings
    People.tsx       patients and staff as two instanced meshes, interpolated by entity id
    Ambulances.tsx, SelectionBox.tsx (corner brackets + pill), CameraRig.tsx (orbit, drift, fly-to)
  modes/             OpsView (Play + Watch), PlayPanel, WatchPanel, CompareView, TradeoffView
  ui/                TopBar, KPI cards, Inspector, EntityList, Journey stepper, Timeline, LineChart
lib/
  types.ts           the contracts as TypeScript
  api.ts             typed client + fixture fallback
  feed.ts            a "feed": one stream of snapshots with its header, layout, hourly series, decisions
  replay.ts          plays recorded rollouts into one or two feeds on a shared clock
  live.ts            WS /ws/sim client
  session.ts         owns the feeds and whichever writer is active; Play controls; human-run POST
  ui.ts              interface state (mode, selection, speed, ...)
scripts/
  make-fixtures.mjs  builds public/fixtures
  mock-server.mjs    stand-in server for the live path
  screenshots.mjs    headless Playwright run that saves PNGs to overnight/screenshots/
```

How the scene stays fast: every box, rounded box and cylinder in the building is one of four instanced meshes; people
are two instanced meshes (bodies, heads). Positions are interpolated per frame inside the render loop without React
re-renders; panels read the feed at most four times a second. The shadow map refreshes on alternate frames.

Conventions the scene relies on: metres, `x` east, `z` south; patients lie down when they are in a bed-type room in an
in-bay state; people who appear or leave scale in and out over 0.4 s; a jump in the stream (scrub, restart) snaps
instead of gliding. Campus buildings in `site.buildings` are context: a footprint under 1 m high is drawn as a flat
ground slab, the others as low massing blocks (22 % of real height, capped at 7 m) so they never hide the department.

## Screenshots

```bash
PLAYWRIGHT_BROWSERS_PATH=.playwright pnpm exec playwright install chromium   # once
pnpm dev                                    # or pnpm start
node scripts/screenshots.mjs http://localhost:3000            # software GL (SwiftShader), slow
node scripts/screenshots.mjs http://localhost:3000 --gpu      # the machine's GPU, fast
node scripts/screenshots.mjs --gpu --offline                  # force the fixture fallback (files web-*.png)
node scripts/screenshots.mjs --gpu --api http://localhost:8000   # against a running server (files web-live-*.png)
```

The script also checks behaviour and prints problems: search selection, list selection, a click in the 3D scene,
timeline scrubbing, Play start/stop, the trade-off click-through, the phone drawer, and that switching hospital
redraws the building.

## Not built here

`/encounter` and `/studio` are placeholders for another workstream. The "Play this encounter" button on a selected
patient links to `/encounter?run_id=..&patient_id=..`.

Assumptions that need the simulator's confirmation are listed in `CONTRACT_REQUESTS.md`.
